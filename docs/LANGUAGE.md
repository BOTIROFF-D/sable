## Синтаксис в целом

Инструкция заканчивается переводом строки; точка с запятой нужна только чтобы
поставить две инструкции в одну строку.

```dbgo
let a = 1
let b = 2; let c = 3
```

Перенос внутри `(…)` и `[…]` значения не имеет — длинный вызов можно разложить
на несколько строк. Выражение, оборванное оператором, тоже продолжается:

```dbgo
let total = price *
            quantity
```

Комментарии: `// до конца строки` и `/* блочные, /* вложенные */ тоже */`.

Тела `if`, `while`, `for`, функций и структур всегда в фигурных скобках.
Условие в скобки брать не нужно.

## Типы и литералы

| Тип | Пример | Заметки |
|---|---|---|
| `number` | `42`, `-7`, `3.5`, `1_000_000`, `0xFF`, `1e3` | одно число с плавающей точкой, как в JS |
| `string` | `"текст"`, `'текст'`, `` `много\nстрок` `` | неизменяемая, индексируется по символам |
| `bool` | `true`, `false` | |
| `nil` | `nil` | отсутствие значения |
| `list` | `[1, "два", nil]` | изменяемый, любые значения вперемешку |
| `map` | `{ name: "Ali", age: 20 }` | порядок вставки сохраняется |
| `range` | `0..10` | ленивый, конец не входит |
| `fn` | `fn(x) { … }`, `x -> x * 2` | значение первого класса |
| структура | `Point(3, 4)` | см. [Структуры](#структуры) |

Проверить тип: `type(v)` возвращает строку (`"number"`, `"list"`, имя структуры).

## Переменные

```dbgo
let счётчик = 0      // можно менять
счётчик += 1

const ЛИМИТ = 100    // менять нельзя — попытка это ошибка
```

Имена могут быть на латинице и кириллице; внутри имени допустим тюркский окина
(`oʻquvchi`, `gʻalaba`). Обычный апостроф в имя не входит — он занят под строку.
Область видимости — блок. Внутренний блок может затенить внешнее имя,
но объявить одно имя дважды в одном блоке нельзя.

## Операторы

По убыванию силы связывания:

| Уровень | Операторы |
|---|---|
| постфикс | `f(…)` `a[i]` `a.b` |
| степень | `^` (правоассоциативна: `2^3^2` = `2^9`) |
| унарные | `-x` `!x` (`not x`) |
| мультипликативные | `*` `/` `%` |
| аддитивные | `+` `-` |
| диапазон | `..` |
| сравнение | `<` `<=` `>` `>=` |
| равенство | `==` `!=` |
| И | `&&` (`and`) |
| ИЛИ | `\|\|` (`or`) |
| «если nil» | `??` |
| тернарный | `? :` |
| присваивание | `=` `+=` `-=` `*=` `/=` |

Тонкости, которые обычно всплывают позже:

- `-2 ^ 2` равно `-4`: степень сильнее унарного минуса, как в математике.
- `==` сравнивает **по содержимому**: `[1, [2]] == [1, [2]]` истинно.
- Ложны только `false` и `nil`. `0` и `""` истинны.
- `&&` и `||` не вычисляют правую часть, если исход уже ясен.
- `??` подставляет запасное значение только вместо `nil`, но не вместо `false` или `0`.
- Деление на ноль — ошибка, а не `inf`.
- `+` не смешивает типы: `"сумма: " + 5` — ошибка, нужно `"сумма: ${5}"` или `str(5)`.

Полезные перегрузки: `"ха" * 3` → `"хахаха"`, `[0] * 3` → `[0, 0, 0]`,
`[1, 2] + [3]` → `[1, 2, 3]`, строки сравниваются лексикографически.

## Строки

```dbgo
let имя = "Мир"
print("Привет, ${имя}! ${2 + 2} = ${"четыре".upper()}")
```

Вставка `${…}` принимает любое выражение, включая вложенные строки.
Экранирование: `\n` `\t` `\r` `\\` `\"` `\'` `` \` `` `\$` `\0` `\u{1F600}`.

Многострочная строка — в обратных кавычках; внутри не нужно экранировать
обычные кавычки, вставки `${…}` работают так же.

Длина и индексы считаются в символах, а не в байтах: `len("абв")` = 3,
`"абв"[-1]` = `"в"`.

**Методы:** `len` `upper` `lower` `trim` `chars` `reverse` `contains(s)`
`starts_with(s)` `ends_with(s)` `index_of(s)` `replace(из, в)` `split(sep?)`
`slice(от, до?)` `repeat(n)` `pad_start(n, ch?)` `pad_end(n, ch?)`

Строки неизменяемы: `s[0] = "а"` — ошибка, соберите новую строку.

## Списки

```dbgo
let xs = [3, 1, 2]
xs.push(4)
print(xs[0], xs[-1], xs.len())
```

Отрицательный индекс отсчитывается с конца. Выход за границы — ошибка,
а не `nil`: молчаливый `nil` прячет опечатки.

**Меняют список:** `push(…)` `pop()` `insert(i, v)` `remove_at(i)`
**Возвращают новый:** `sort(cmp?)` `reverse()` `slice(от, до?)` `clone()` `map(f)` `filter(f)`
**Отвечают на вопрос:** `len()` `first()` `last()` `contains(v)` `index_of(v)` `find(f)` `any(f)` `all(f)` `reduce(f, начало)` `join(sep?)`

```dbgo
let names = ["Vali", "Ali", "Gulnoz"]
print(names.sort().join(", "))
print(names.filter(n -> n.len() > 3).map(n -> n.upper()))
print(names.reduce((acc, n) -> acc + n.len(), 0))
```

`sort()` без аргумента упорядочивает числа или строки; для остального передайте
функцию сравнения, возвращающую отрицательное, ноль или положительное:

```dbgo
students.sort((a, b) -> b.paid - a.paid)
```

Колбэк получает `(значение, индекс)`, но вправе взять только первый аргумент.

## Словари

```dbgo
let u = { name: "Ali", age: 20 }
print(u.name, u["age"])
u.age = 21
u["city"] = "Bukhara"
```

Ключом может быть строка, число или `bool`. Вычисляемый ключ — в квадратных
скобках: `{ [переменная]: 1 }`.

Доступ через точку сначала ищет **данные**, и только потом метод — чтобы
`u.name` работал независимо от того, как называются методы. Если данные и метод
называются одинаково, зовите метод как свободную функцию: `keys(u)`, `len(u)`.

`u["нет"]` для отсутствующего ключа — ошибка; `u.get("нет", запасное)` — нет.

**Методы:** `len()` `keys()` `values()` `entries()` `has(k)` `get(k, запасное?)`
`set(k, v)` `remove(k)` `clone()` `merge(другой)`

Словарь в заголовке `if`/`while`/`for` нужно взять в скобки — иначе `{`
прочитается как начало тела:

```dbgo
for key in ({ a: 1, b: 2 }) { print(key) }
```

## Диапазоны

`начало..конец` — конец не входит. Диапазон ленив: `0..1000000` не создаёт
миллион элементов, пока вы не позовёте `.list()`.

```dbgo
for i in 0..5 { write(i, " ") }     // 0 1 2 3 4
print((1..4).list(), (0..5).len(), (0..5).contains(5))
```

Нужен шаг или обратный порядок — `range(от, до, шаг)`: `range(10, 0, -2)`.

## Управление

```dbgo
if x > 10 { print("много") }
else if x > 5 { print("средне") }
else { print("мало") }

while условие { … }

for элемент in последовательность { … }
```

`for` проходит по списку, строке (по символам), диапазону и словарю (по ключам).
`break` и `continue` работают в обоих циклах.

Каждая итерация `for` получает **свою** переменную цикла — замыкания, созданные
внутри, запомнят разные значения:

```dbgo
let fns = []
for i in 0..3 { fns.push(fn() -> i) }
print(fns.map(f -> f()))   // [0, 1, 2]
```

Тернарный оператор — выражение, а не инструкция:

```dbgo
let подпись = долг > 0 ? "должник" : "оплачено"
```

## Функции

```dbgo
fn площадь(ширина, высота = ширина) {
  return ширина * высота
}
```

Значение по умолчанию вычисляется при вызове и **видит предыдущие параметры**.
Параметр без значения по умолчанию не может стоять после параметра с ним.
Функция без `return` возвращает `nil`.

Три способа записать функцию-значение:

```dbgo
let a = fn(x) { return x * x }   // полная
let b = fn(x) -> x * x          // тело-выражение
let c = x -> x * x              // один параметр
let d = (x, y) -> x * y         // несколько параметров
```

Функции — обычные значения: их можно передавать, возвращать и хранить.
Замыкание помнит окружение, в котором создано:

```dbgo
fn счётчик() {
  let n = 0
  return fn() { n += 1; return n }
}
let next = счётчик()
print(next(), next(), next())   // 1 2 3
```

Имя функции ищется в момент вызова, а не объявления, поэтому взаимная рекурсия
работает — важно лишь, чтобы обе функции были объявлены до первого вызова.

## Структуры

```dbgo
struct Студент {
  имя
  оплачено = 0
  fn должник() { return self.оплачено == 0 }
  fn с_оплатой(сумма) { return Студент(self.имя, self.оплачено + сумма) }
}

let s = Студент("Ali")
print(s.должник(), s.с_оплатой(450000).оплачено)
```

Поля перечисляются по порядку, возможны значения по умолчанию.
Экземпляр создаётся вызовом имени структуры; аргументы позиционные.
В методах `self` — текущий экземпляр; поля можно менять.

Присваивание несуществующему полю — ошибка: это ловит опечатки.
Два экземпляра одной структуры равны, если равны все поля.
`to_json(экземпляр)` превращает его в объект JSON.

## Модули

Программу можно разложить по файлам.

```dbgo
// lib/math.dbgo
const PI2 = 6.283185307179586
fn площадь(r) { return PI2 / 2 * r ^ 2 }
struct Вектор { x, y }
```

```dbgo
// main.dbgo
import "lib/math.dbgo" as math

print(math.площадь(2))
print(math.Вектор(3, 4).x)
```

Правила короткие:

- Путь считается **от папки файла, который импортирует**, а не от места запуска.
- Экспортируется **всё, объявленное на верхнем уровне** модуля: `let`, `const`,
  `fn`, `struct`. Отдельного слова для этого нет.
- Файл выполняется **ровно один раз**, сколько бы модулей его ни подключили.
  Печать и другие побочные эффекты модуля не повторяются.
- `import` разрешён только на верхнем уровне файла.
- Имена модуля менять нельзя: `math.площадь = …` — ошибка.
- Циклический импорт ловится и печатает всю цепочку, а не зацикливается.

Обращение к тому, чего в модуле нет, подсказывает ближайшее имя:

```text
Ошибка выполнения: в модуле «math» нет имени «площад» — возможно, имелось в виду «площадь»
```

Ошибка внутри модуля показывает строку **своего** файла, а не главного.

## Ошибки

Свою ошибку бросают через `error(значение)`; проверку — через `assert(условие, сообщение?)`.

```dbgo
fn снять(баланс, сумма) {
  if сумма > баланс { error("недостаточно средств: нужно ${сумма}, есть ${баланс}") }
  return баланс - сумма
}
```

Непойманная ошибка останавливает программу и печатает место, строку исходника
со стрелкой и стек вызовов.

Ошибку можно перехватить:

```dbgo
fn снять(баланс, сумма) {
  if сумма > баланс { error("недостаточно средств: нужно ${сумма}, есть ${баланс}") }
  return баланс - сумма
}

try {
  print("осталось ${снять(100, 30)}")
  print("осталось ${снять(100, 500)}")
} catch e {
  print("не вышло:", e.message)
}
```

```text
осталось 70
не вышло: недостаточно средств: нужно 500, есть 100
```

Пойманное — всегда словарь с одними и теми же ключами, независимо от того,
откуда пришла ошибка:

| Ключ | Что внутри |
|---|---|
| `message` | текст ошибки |
| `value` | то, что передали в `error(…)`; `nil` для встроенных ошибок |
| `file`, `line`, `column` | где произошло |

Поэтому `e.message` работает всегда, а `e.value` нужен, когда вы бросали не
строку, а свои данные:

```dbgo
try { error({ код: 404, текст: "не найдено" }) }
catch e { print(e.value.код, e.value.текст, e.message) }
```

```text
404 не найдено {"код": 404, "текст": "не найдено"}
```

Имя переменной необязательно: `catch { … }`. `try` без `catch` — синтаксическая
ошибка, а не молча проглоченный блок.

Ловятся только ошибки выполнения. `return`, `break` и `continue` проходят сквозь
`try` насквозь — иначе `return` изнутри `try` перестал бы выходить из функции.

## Стандартная библиотека

**Вывод и ввод**
`print(…)` через пробел с переводом строки · `write(…)` без перевода ·
`input(приглашение?)` строка со stdin, `nil` в конце ввода ·
`read_file(путь)` · `write_file(путь, текст)`

**Типы и преобразование**
`type(v)` · `str(v)` · `repr(v)` как в коде · `num(v, запасное?)` · `int(v)` отбрасывает дробь · `bool(v)` · `len(v)`

**Числа**
`abs` `floor` `ceil` `round(n, знаков?)` `sqrt` `pow(a, b)` `min(…)` `max(…)`
`sign(n)` -1, 0 или 1 · `clamp(n, мин, макс)` загоняет число в границы ·
`random()` в \[0, 1) · `random_int(от, до)` включая обе границы

`round` округляет половину от нуля: `round(2.5)` = 3, `round(-2.5)` = -3.
`clamp` требует `мин <= макс` — перепутанные границы это ошибка, а не тихий разворот.

**Математика**
`exp(n)` · `log(n, основание?)` без основания — натуральный ·
`hypot(a, b, …)` длина вектора · `sin` `cos` `tan` `asin` `acos` `atan`
`atan2(y, x)` · `pi()` число π

`log(1000, 10)` = 3 и `log(8, 2)` = 3 ровно: двойка и десятка считаются отдельно,
через деление логарифмов вышло бы 2.9999999999999996. `log(0)`, `asin(2)`,
`log(n, 1)` — ошибки: вне области определения.

π — функция `pi()`, а не имя `PI`: встроенное имя нельзя перекрыть своим
`let`/`const`, и константа отняла бы у программы ходовое имя. Нужна константа —
`const PI = pi()` в начале файла. Число e даёт `exp(1)`.

**Последовательности**
`range(до)` `range(от, до)` `range(от, до, шаг)` · `map(seq, f)` `filter(seq, f)`
`reduce(seq, f, начало)` `sum(seq)` · `zip(a, b)` пары бок о бок, лишний хвост
отбрасывается · `enumerate(seq)` пары `[индекс, значение]` ·
`sorted(seq, сравнение?)` `reversed(seq)` — всегда новый список ·
`from_entries(пары)` собирает словарь из списка `[ключ, значение]`

Все они работают со списком, строкой и диапазоном; `sorted("бав")` вернёт
`["а", "б", "в"]` — список символов, а не строку. `sorted` берёт функцию
*сравнения* (как `sort`), а не ключа; ключ — это `sort_by`.

**Словари**
`keys(m)` `values(m)` `entries(m)` — то же, что методы, но не спорят с ключами

**JSON**
`to_json(v, отступ?)` · `from_json(текст)` — объекты становятся словарями

**Прочее**
`assert(условие, сообщение?)` · `error(значение)` · `now()` миллисекунды ·
`clock()` секунды с дробью, для замеров

### Ещё методы списка

**Считают:** `sum()` `avg()` `count(f_или_значение)` `sum_by(f)` `min_by(f)` `max_by(f)`
**Возвращают новый список:** `unique()` `flatten(глубина?)` `take(n)` `drop(n)`
`chunk(n)` `zip(другой)` `enumerate()` `sort_by(f)` `flat_map(f)` `partition(f)`
**Прочее:** `is_empty()` `group_by(f)` → словарь

```dbgo
let люди = [{ имя: "Ali", возраст: 30 }, { имя: "Vali", возраст: 25 }]
print(люди.sum_by(p -> p.возраст))              // 55
print(люди.min_by(p -> p.возраст).имя)          // Vali
print(люди.group_by(p -> p.возраст).keys())     // [30, 25]
print(range(1, 11).filter(n -> n % 3 != 0).chunk(3).map(c -> c.sum()))
```

- `avg()` у пустого списка — ошибка: среднее не из чего считать. `sum()` пустого — 0.
- `min_by`/`max_by` тоже требуют непустой список и возвращают **элемент**, а не ключ;
  из равных берётся первый.
- `sort_by` устойчива: элементы с одинаковым ключом сохраняют исходный порядок.
  Ключом может быть число или строка; убывание — `sort_by(p -> -p.цена)`.
- `count` понимает и функцию, и значение: `xs.count(1)` считает единицы,
  `xs.count(x -> x > 3)` — подходящие под условие.
- `flatten()` без аргумента разворачивает до конца, `flatten(1)` — на один уровень.
  Список, который ссылается сам на себя, при полном развороте даёт ошибку, а не зависание.
- `group_by` требует, чтобы функция вернула ключ словаря — строку, число или bool.
- `flat_map` требует список от функции: `[1].flat_map(x -> x)` — ошибка, нужно `x -> [x]`.
- `zip` обрезает по короткому, `chunk` отдаёт последний кусок неполным,
  `take`/`drop` не спорят с числом больше длины, но ругаются на отрицательное.

### Ещё методы строки

`lines()` `words()` `capitalize()` `title()` `is_empty()` `count(подстрока)`
`trim_start()` `trim_end()` `split_once(sep)` `format(…)`

```dbgo
let csv = "имя,цена\nхлеб,5000\nмолоко,12000"
let строки = csv.lines()
let заголовки = строки.first().split(",")
print(строки.drop(1).map(r -> from_entries(zip(заголовки, r.split(",")))))
print("Здравствуйте, {}! Баланс — {} сум.".format("Ali", 12000))
```

- `lines()` понимает и `\r\n`, и последний перевод строки не даёт пустой строки в конце:
  `"а\nб\n".lines()` — две строки, а не три.
- `words()` режет по любым пробелам и не оставляет пустых слов.
- `capitalize()` и `title()` поднимают первую букву (слова) и **не трогают остальное**:
  `"iPhone".capitalize()` — `"IPhone"`. Нужен полный разбор регистра — `.lower().title()`.
- `count(подстрока)` считает без наложений: `"aaaa".count("aa")` = 2. Пустая подстрока — ошибка.
- `split_once(sep)` режет по первому вхождению и отдаёт две части либо `nil`,
  если разделителя нет: `"k=v=w".split_once("=")` → `["k", "v=w"]`.
- `format(…)` подставляет аргументы в `{}` по порядку. Подстановок и аргументов
  должно быть поровну, иначе ошибка. Экранирования нет: `{}` в шаблоне — всегда дырка.
  Для строки, известной на месте, короче обычная вставка `${…}`.

### Ещё методы словаря

`map_values(f)` `filter(f)` `pick(ключи)` `omit(ключи)` `is_empty()` `get_or_insert(k, v)`

```dbgo
let цены = { хлеб: 5000, молоко: 12000, сыр: 45000 }
print(цены.map_values(v -> v / 1000))       // {"хлеб": 5, "молоко": 12, "сыр": 45}
print(цены.filter(v -> v > 10000).keys())   // ["молоко", "сыр"]
print(цены.pick(["сыр", "хлеб"]))           // {"сыр": 45000, "хлеб": 5000}
```

- Колбэк в `map_values` и `filter` получает `(значение, ключ)` — лямбде с одним
  параметром достаётся значение, оно нужно чаще.
- `map_values`, `filter`, `pick`, `omit` возвращают **новый** словарь, исходный не трогают.
- `pick` идёт по списку ключей, а не по словарю, — порядок задаёте вы; отсутствующие
  ключи просто пропускаются.
- `get_or_insert(k, v)` кладёт `v`, только если ключа ещё нет, и возвращает то,
  что теперь лежит по ключу. Это единственный из новых методов, который **меняет**
  словарь на месте — на нём удобно копить:

```dbgo
let корзины = {}
корзины.get_or_insert("фрукты", []).push("яблоко")
корзины.get_or_insert("фрукты", []).push("груша")
print(корзины)                              // {"фрукты": ["яблоко", "груша"]}
```

## Проверка без запуска

`dbgo --check файл.dbgo` проходит по программе, не выполняя её, и находит
неизвестные имена, запись в `const`, повторные объявления, `break` вне цикла,
недостижимый код, неверное число аргументов, опечатки в полях структур и
забытые переменные.

Проверка намеренно не встроена в обычный запуск: она судит о программе по
одному тексту и может ошибиться там, где программа рабочая — например про имя,
до которого дело доходит только внутри `try`.
